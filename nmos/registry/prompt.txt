In order to allow users to as easy as possibly try the nmos-reference project I figured out that I need to provide my own NMOS registry such that there is no complex pre-required installation of a regsitry. we need to implement nmos/registry as a fully compliant registry with the NMOS specs in the nmos/regsitry/specs folder. 

nmos/registry/specs has most of the query and registration RAML and JSON check https://github.com/AMWA-TV/is-04/tree/v1.3.x/APIs/schemas for missing ones

An example of Registry is available in the NMOS test suite mock registry IPMX-testing/nmostesting/mocks/Registry.py WE must match in behavior with it unless you discover it does not match the specifications Behaviour - Querying.md and Behaviour - Registration.md

The nmos-cpp project also serves as a reference https://github.com/sony/nmos-cpp/tree/master/Development/nmos-cpp-registry

First make sure we have all the required types available in nmos-reference/nmos/codegen/definitions/is04_types.py Is we are missing some then they must be created as definition the then generate the types.

The controller must follow the coding style and reuse the existing subsystems of the Node and Controller and be using the same HTTP handler subsystem. the query interface of the registry must support all the modes of a Node (no TLS, TLS server auth, mTLS mutual auth, OAuth2.0 + TLS server auth, OAuth2.0 + mTLS mutual auth). The registration interface  of the registry must support the modes noTLS, TLS server auth, mTLS mutual auth. Note that there is no AUth1.0 for the Registration interface.

The command line parameters must match those of the Node and a similar pattern must be used.

Project must follow the fully types python3 style of the other nmos-reference modules.

Make this python3 based registry fully functional and compliant with the NMOS specification will allow us in the future to move to a Rust implementation to get the highest performance.

the registry should be a stand alone application, not embedded in the Node as we've done for the Controller names nmos_registry.py

Have a status similar to nmos-cpp every N seconds "At 1785684536:107763, the registry contains 1 resources (1 nodes, 0 devices, 0 sources, 0 flows, 0 senders, 0 receivers, 0 subscriptions, 0 grains), most recent update: 1785604718:431043782, least health: 1785684536, 0 non-extant resources"
